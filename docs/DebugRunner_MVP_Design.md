# DebugRunner — MVP 設計書

> 「バグを直すか、利用するか——未完成ゲームをテストしているはずが、最後に修正対象になる2Dメタアクション。」

個人開発／短編MVP（Steam体験版・itch.io公開想定 / プレイ時間10〜20分 / ステージ3〜5）向けの実装可能設計書。

---

## 1. 企画概要

### 一言コンセプト
**「バグを“直す”か“使う”かで進路が変わる、未完成ゲームのデバッグ・メタアクション。最後に直されるのはプレイヤー自身。」**

### ジャンル
2Dアクションパズル × デバッグゲーム × メタ演出（横スクロール）

### コアの面白さ
- 普通の2Dアクションだと思ってプレイ開始 → **バグが発生** → デバッグパネルで「修正 / 放置」を選べる。
- **直すと安全だが進めない／放置するとバグを踏み台にして突破できる**、というジレンマ。
- 修正には**副作用**があり、直すほど別の場所が壊れる。
- 終盤は**ゲーム画面だけでなくUI・ログ・メニュー・デバッグ画面そのもの**が侵食される。
- ホラーではなく「**不気味・メタ・びっくり**」。怖がらせるより“ゾッ”とさせる。

### プレイヤーが最初の30秒で理解する体験
1. **0–10秒**：左右移動＋ジャンプで進む、ごく普通の横スクロールアクション。画面右上に小さく `BUILD v0.3.1 (TEST)` の表示。
2. **10–20秒**：足場が一瞬チラつく → 床をすり抜けて落ちかける、という**最初のバグ**に遭遇。「あれ？」という違和感。
3. **20–30秒**：画面に `! BUG DETECTED` のトーストが出て、**[TAB] DEBUG** の入力ガイドが点滅。開くとデバッグパネルが立ち上がり、「**FIX / IGNORE**」の2択が提示される。
   → ここで「これは“デバッグするゲーム”だ」と理解が完成する。

## 2. MVPの完成形

- **プレイ時間**：10〜20分（1周クリアまで）
- **ステージ数**：5（チュートリアル＋4本）
- **バグ種類**：6種（コア）
- **エンディング**：1本（ラストの「プレイヤー＝修正対象」演出までを完成形とする）
- **対応**：PC（キーボード＋ゲームパッド）、横画面16:9
- **推奨エンジン**：Godot 4（2D・軽量・無料・メタ演出向きのCanvasLayer/Shader）または Unity 2D。本書はGodot 4を主軸に記述（Unityでも読み替え可能な抽象度で記載）。

完成形の定義（Definition of Done）：
- 5ステージを通しでプレイでき、各ステージに「修正ルート」と「利用ルート」が最低1つずつ成立する。
- バグ6種すべてが「発生→2択→結果（副作用含む）」のループとして機能する。
- 演出4段階（違和感→UI異変→デバッグ画面侵食→プレイヤーが対象）がすべて発火する。
- タイトル／クリア画面が存在し、最初から最後まで止まらず遊べる。

## 3. ゲームループ

### 全体ループ（マクロ）
```
タイトル → ステージ開始 → 探索/アクション → バグ発生
  → デバッグパネル起動([TAB]) → [FIX] or [IGNORE] を選択
     → FIX:  そのバグ解消、ただし別の場所に副作用が発生
     → IGNORE: バグが残り、攻略の踏み台として利用できる
  → 副作用/利用を踏まえて先へ進む → ステージクリア → 次ステージ
  → 終盤: UI/ログ/デバッグ画面が侵食 → ラスト演出 → エンディング
```

### 1ステージ内ループ（ミクロ）
1. 進む（アクション）
2. 行き止まり or 異常に遭遇（＝バグ）
3. デバッグパネルを開いて状況を読む
4. 「直す／使う」を決める（ここが意思決定の核）
5. 結果（副作用 or 突破ルート）に対処
6. ゴールへ

**1ステージあたり「決定ポイント」2〜3個**を目安に設計する。

## 4. 操作方法

| 入力（キーボード） | ゲームパッド | アクション |
|---|---|---|
| ←→ / A・D | 左スティック | 移動 |
| Space / W / ↑ | A(下) | ジャンプ |
| Shift | RT/R2 | ダッシュ（任意・後回し可） |
| **TAB** | **Y(上)** | **デバッグパネル開閉** |
| ↑↓ or マウスホバー | 十字キー上下 | デバッグ項目の選択 |
| Enter / 左クリック | A(下) | FIX / IGNORE 決定 |
| E | X(左) | 調べる／スイッチ操作 |
| Esc | Start | メニュー（後半で侵食対象） |

操作は**「移動・ジャンプ・調べる・デバッグ」**の4つに絞る。戦闘ボタンは作らない（後述）。

## 5. 画面構成

### 5-1. アクション画面（メインゲームプレイ）
- 16:9、横スクロール。手前にプレイヤー、奥に背景レイヤー1〜2枚。
- **常時HUD**：左上にステージ名、右上に小さく `BUILD vX.X.X (TEST)`。この「ビルド表示」がメタ感の起点。
- バグ発生時：画面隅に `! BUG DETECTED [TAB]` トースト＋対象オブジェクトに**赤いハイライト枠／ノイズ**。

### 5-2. デバッグパネル
- [TAB]で**ゲームに半透明オーバーレイ**として乗る（背景のゲームは薄暗く一時停止 or 低速）。
- 構成：
  - 上部：`DEBUG CONSOLE` タイトル＋検出バグのID（例 `BUG#04 PLATFORM_COLLISION`）
  - 中央：**バグ説明文**（1〜2行、開発者コメント風。例: `// platform collider disabled? -kj`）
  - 下部：**[ FIX ] / [ IGNORE ]** の2ボタン
  - 右側：副作用プレビューの“ヒント”（後半は嘘・文字化けが混じる）
- **後半**：このパネル自体に文字化け・ボタンの増殖・「閉じない」などの侵食が起きる。

### 5-3. エラーログ
- 画面下部に開閉式の**コンソールログ**（`~` キー or パネル内タブ）。
- 序盤：淡々とした正常ログ（`[INFO] player spawned` など）。
- 中盤：警告が増える（`[WARN] entity out of bounds`）。
- 終盤：プレイヤー名や“あなた”を指すログが混入（`[ERROR] tester is not supposed to read this`）。
- **演出装置として最重要**。実ゲームロジックと無関係でも、雰囲気の8割をここで作れる。

### 5-4. タイトル／メニュー画面
- タイトル：`DebugRunner` ロゴ＋`v0.3.1 (TEST BUILD)`＋[ START TEST ] [ OPTIONS ] [ QUIT ]。
- **後半でタイトルに戻ると**、ロゴが欠けている／メニュー項目が増えている／`[ QUIT ]` が選べない、等の変化。
- 一時停止メニュー：Resume / Restart Stage / Quit。終盤は `Quit` が `Quit?` → `(disabled)` に変化。

## 6. コアメカニクス

### 6-1. バグの発生
- 各バグは**トリガーゾーン**（プレイヤーが特定エリアに入る／スイッチを踏む）で発火。
- 発火すると：①対象オブジェクトに視覚的グリッチ ②`! BUG DETECTED` トースト ③デバッグパネルにそのバグIDが登録。
- 実装：`Bug` ノード（state: `dormant / active / fixed / exploited`）＋トリガー領域。

### 6-2. バグ修正（FIX）
- パネルで [FIX]。対象バグの“正しい挙動”に戻す（コライダ復活、扉が開く、重力が正常化…）。
- メリット：安全・想定どおりの足場で進める。
- デメリット：**必ず副作用が1つ発火**（別オブジェクトが壊れる／別ルートが塞がる）。
- 実装：`bug.fix()` → 対象を正常stateへ＋`trigger_side_effect(id)`。

### 6-3. バグ利用（IGNORE / EXPLOIT）
- パネルで [IGNORE]、またはパネルを開かず**バグをそのまま物理的に使う**。
- バグが攻略の踏み台になる（すり抜けでショートカット、低重力で大ジャンプ、敵AIの誤作動で敵が自滅…）。
- メリット：早い・ズルい・気持ちいい。隠しルートに繋がることも。
- デメリット：不安定（タイミングがシビア／ログが荒れる／後半の侵食が早まる“バグ負債”）。

### 6-4. 修正の副作用
- 設計原則：**FIXは「今ここ」を解決し、「別のどこか」を壊す**。
- 副作用は基本「次のセクション or 直近の既出オブジェクト」に出し、プレイヤーが因果を理解できる距離に置く。
- **侵食度（Corruption）グローバル変数**を持ち、FIX回数・IGNORE放置に応じて加算。閾値で演出段階が進む（§10）。
  - 例：`corruption += 1`（FIXごと）／放置バグ数に応じてログ荒れ係数アップ。

|---|---|---|
| BUG#01 | 足場判定バグ (PLATFORM_COLLISION) | 床をすり抜ける |
| BUG#02 | 扉バグ (DOOR_STATE) | 開くべき扉が開かない/開きっぱ |

## 8. 各バグ詳細

### BUG#01 足場判定バグ（PLATFORM_COLLISION）
- **発生状況**：チュートリアル中盤、特定の床に乗ると床のコライダが消える。
- **影響**：床をすり抜けて下へ落下（即死ではなく下の段へ）。
- **FIXした場合**：床が固体化し普通に渡れる。**副作用**：その先の壁も“固体化しすぎて”通常開く隙間が塞がる→別ルート必要。
- **利用攻略**：あえて落下し、本来行けない下層のショートカット／隠しアイテムへ。
- **副作用**：FIXで `corruption +1`、隣接プラットフォームのテクスチャがチラつき始める。

### BUG#02 扉バグ（DOOR_STATE）
- **発生状況**：ゴール手前の扉。スイッチを踏んでも状態フラグが反転しない。
- **影響**：扉が開かず行き止まり（or 逆に閉じられない）。
- **FIXした場合**：扉のstateが正常化し開閉できる。**副作用**：同じstate系を共有する“別の扉”が逆に誤作動（開いてた所が閉じる）。
- **利用攻略**：扉を「開きっぱバグ」のまま利用して、本来ロックされた区画を素通り。
- **副作用**：放置するとログに `[WARN] door state desync x N` が累積し侵食加速。

### BUG#03 重力バグ（GRAVITY_SCALE）
- **発生状況**：縦穴エリアで重力スケールが0.3に低下（or 反転）。
- **影響**：ジャンプが異常に伸びる／落下が遅い／天井に落ちる。
- **FIXした場合**：重力正常化で精密ジャンプが可能に。**副作用**：近くの“浮いている足場”が低重力前提だったため落下・消失。
- **利用攻略**：低重力のまま大ジャンプで高所の隠しルート／一気に上のゴールへ。
- **副作用**：FIX/利用どちらでも、カメラが酔うように微振動（演出）。

### BUG#04 敵AIバグ（ENEMY_AI）
- **発生状況**：パトロール敵がプレイヤーを見失い、壁に向かって突進し続ける。
- **影響**：敵が予測不能（こっちを無視 or 無限ループ移動）。
- **FIXした場合**：敵AIが正常化＝**ちゃんと襲ってくる**（FIXがリスクになる珍しい例）。**副作用**：他の敵も“起きて”活性化。
- **利用攻略**：壁ドン中の敵を足場にする／自滅させて道を開ける（敵が穴に落ちる等）。
- **副作用**：放置敵が時間経過で増殖グリッチ（軽い不気味演出、無害だが画面が騒がしくなる）。

### BUG#05 カメラバグ（CAMERA_CLAMP）
- **発生状況**：エリア境界でカメラのクランプが外れ、画面外（開発用の“裏側”）が見える。
- **影響**：視界がずれてプレイしづらい／一方で**隠し情報やルートが見える**。
- **FIXした場合**：カメラ正常化で見やすくなる。**副作用**：見えていた“裏ルートの入口ヒント”が二度と見えなくなる。
- **利用攻略**：ズレた視界で、本来隠されたスイッチ・通路・次バグの伏線を発見して攻略。
- **副作用**：放置すると終盤、カメラが“勝手にプレイヤーを覗き込む”ような寄りを始める（びっくり演出の布石）。

### BUG#06 UI実体化バグ（UI_COLLIDER）★メタの目玉
- **発生状況**：UI侵食ステージで、HUDの文字やログウィンドウ、トーストが**ゲーム内の当たり判定を持つ**。
- **影響**：画面に出た `! BUG DETECTED` の文字や体力バーが**足場・障害物**になる。
- **FIXした場合**：UIが当たり判定を失い、画面が“きれい”に。**副作用**：その当たり判定を足場にして渡る前提の場所だと、**渡れなくなって詰みかける**（→別バグの利用が必要）。
- **利用攻略**：UI文字を足場・壁としてジャンプ。ログを階段にして登る。デバッグパネルのボタンに乗る。
- **副作用**：UIに乗るほどUIが破損し、最終的にデバッグパネル自体が侵食される（§10終盤へ接続）。

## 9. ステージ設計（5ステージ）

### STAGE 0 — チュートリアル「TEST BUILD v0.3.1」
- **目的**：基本操作＋「バグは直すか使うか選べる」を教える。
- **使うバグ**：BUG#01（足場判定）。
- **流れ**：普通に進む→床すり抜け→[TAB]強制ガイド→FIX/IGNORE両方を“試させる”小部屋（リトライ可）→ゴール。
- **学習**：FIXは安全だが副作用、IGNOREは抜け道、を体験で理解。
- **演出段階**：①軽い違和感（ビルド表示・床チラつき）。

### STAGE 1 — バグ利用ステージ「Shortcut」
- **目的**：「直さず使うと得をする」を強く体感させる。
- **使うバグ**：BUG#03（重力）＋BUG#05（カメラ）。
- **流れ**：正攻法だと遠回り→重力バグを“利用”で大ジャンプ近道／カメラバグで隠しルート発見。FIXすると遠回りだが安全な道。
- **分岐**：利用ルート（速い・隠しコイン）／修正ルート（安全・素直）。
- **演出段階**：①〜②の入口（ログに最初の `[WARN]`、隠し部屋に開発メモ）。

### STAGE 2 — 複数バグ組み合わせステージ「Side Effects」
- **目的**：FIXの副作用が連鎖することを学ぶ。「直す順番」がパズルになる。
- **使うバグ**：BUG#02（扉）＋BUG#04（敵AI）＋BUG#01再登場。
- **流れ**：扉を直すと別の扉が閉じる／敵AIを直すと襲ってくる。**どれを直し、どれを残すか**の組み合わせで突破。最低2通りの解。
- **パズル核**：副作用の連鎖を読み、放置と修正を配合する。
- **演出段階**：②UI/ログの異変（ログにプレイヤーを指す行、HUDが一瞬ぶれる、トーストが重なる）。

### STAGE 3 — UI侵食ステージ「The Interface」
- **目的**：メタ演出の本領。UIがゲームの一部になる。
- **使うバグ**：BUG#06（UI実体化）＋既出バグの再利用。
- **流れ**：HUD文字・ログ・体力バーが足場/障害物に。UIに乗って登る→FIXすると足場が消えるので“どのUIを実体化させ続けるか”を選ぶ。終盤、**デバッグパネルのボタン自体に乗る**。
- **演出段階**：③デバッグ画面が侵食される（パネルに文字化け、ボタン増殖、`IGNORE` が `IGN0RE`、説明文が「君を見ている」系へ）。

### STAGE 4 — ラストステージ「Patch」
- **目的**：「プレイヤー自身が修正対象になる」回収。
- **使うバグ**：全部の総合＋“プレイヤー”がバグ扱いされる新イベント。
- **流れ**：デバッグパネルを開くと、検出バグが `BUG#?? : TESTER_PRESENCE`（あなたの存在）になっている。FIX対象が**プレイヤー自身**。
  - [FIX] を押すと…プレイヤーが「正常化＝削除/初期化」される演出 → 画面がビルド画面に戻り、`tester removed. build is now stable.`。
  - [IGNORE]（あるいは“逃げる”）を選ぶと…未完成のまま世界に残る別エンド余地（MVPはまず1エンド、片方を本線に）。
- **演出段階**：④プレイヤー自身が修正対象。タイトル/メニュー/ログすべてがプレイヤーに言及。
- **MVP割り切り**：エンディングは1本（[FIX]=“直される”本線）を完成させる。[IGNORE]側は拡張で。

## 10. びっくり演出の段階設計（4段階）

| 段階 | タイミング | 内容 | 実装の軽さ |
|---|---|---|---|
| **序盤：軽い違和感** | STAGE0–1 | ビルド表示 `(TEST)`、床/テクスチャの一瞬チラつき、開発者コメント風のバグ説明、ログに小さな `[WARN]` | テキスト＋短いシェーダ点滅のみ。安い。 |
| **中盤：UI/ログの異変** | STAGE2 | ログにプレイヤー（tester）を指す行、HUDの数値が一瞬化ける、トーストが重なって出る、メニューの項目が1つ増える | UIラベル差し替え＋ログ生成ルール変更。安い。 |
| **終盤：デバッグ画面侵食** | STAGE3 | デバッグパネルが文字化け、ボタン増殖/位置ズレ、`IGNORE→IGN0RE`、説明文が“こちらを見ている”系、パネルが一瞬閉じない | パネルUIに「侵食モード」スタイル切替＋ランダム配置。中。 |
| **ラスト：プレイヤーが対象** | STAGE4 | 検出バグ＝`TESTER_PRESENCE`、FIX対象がプレイヤー、画面/ログ/タイトルが“君を直す”と告げ、最後にビルドが「安定した」と表示 | 既存パネル＋専用イベント1本。中。 |

設計ルール：
- **音で驚かす > 大量演出**。グリッチ音・無音化・短いビープを要所に。
- びっくりは**「予告→外し→本命」**。トーストや小グリッチで慣れさせ、肝心の所で“静かに”ズラす。
- 怖がらせない：血・絶叫なし。**「画面の向こうがこちらに気づく」**不気味さで止める。

## 11. 最低限必要なアセット一覧

### グラフィック
- プレイヤースプライト：idle / run / jump / fall / “glitch（破損）”の5状態（小ドットでOK）
- タイルセット1種：床・壁・足場・背景（テスト用グリッド調が世界観に合致＝量産が楽）
- 敵スプライト1種：walk＋“bug化”差分
- 扉・スイッチ・ゴール旗
- バグ用グリッチ素材：ノイズテクスチャ、赤ハイライト枠、走査線
- UIパーツ：HUDフォント、トースト枠、デバッグパネル枠、ボタン（normal/hover/破損）
- タイトルロゴ（正常版／欠け版）

### サウンド
- BGM：通常用1（淡々）＋侵食用1（不協和/ローファイ崩し）
- SE：ジャンプ、着地、スイッチ、扉、バグ検出（ビープ）、FIX確定、グリッチ、びっくり用スティンガー1
- 終盤の“無音/ホワイトノイズ”素材

### テキスト
- バグ説明文（開発者コメント風）×6＋侵食版
- ログ文面ルール（正常/警告/侵食の3トーン）
- ストーリー演出文（ラスト用）

**量産のコツ**：世界観が「テストビルド」なので、**わざと素朴なドット＋デバッグ罫線**で押し切れる＝アセット負荷が下がる。これは弱点を世界観に変換する重要設計。

## 14. 作らないほうがいい要素（スコープ防衛）

- **本格的な戦闘システム**（攻撃ボタン・体力・敵多種）→ 敵は“ギミック/足場/自滅”に限定。
- **ランダム生成/オープンワールド**→ 手作り5ステージで十分。
- **複数エンディングの全実装**→ MVPは1エンド。分岐は拡張へ。
- **本物のセーブ/設定の作り込み**（解像度・キーコンフィグ詳細）→ 最低限。
- **ボイス/大量カットシーン**→ テキスト＋小演出で代替。
- **オンライン要素・実績連携**→ 完全に後回し。
- **“本当に”ゲームを壊すバグ表現**（実クラッシュ風）→ 制御可能な“演出としての”侵食に留める（戻れなくなる事故を防ぐ）。
- **過剰なホラー演出**（流血・絶叫・ジャンプスケア乱発）→ 企画方針に反する。

## 16. PV構成（この企画が面白く見える見せ方）

想定45〜60秒。

1. **0–5秒｜掴み**：ごく普通の2Dアクション。「普通のレトロアクション？」と油断させる。右上の `(TEST BUILD)` をさりげなく見せる。
2. **5–12秒｜異変**：床をすり抜けて落下。`! BUG DETECTED`。**[TAB]でデバッグパネル**が開く瞬間を強調。
3. **12–22秒｜選択の妙**：同じバグを「FIXで安全に渡る」→「IGNOREで抜け道に使う」の**2パターンを並べて見せる**（このゲームの核）。
4. **22–32秒｜副作用と組み合わせ**：直したら別の場所が壊れる連鎖をテンポよく。
5. **32–42秒｜メタ侵食**：UI文字が足場になる、ログに“tester…”、デバッグパネルが文字化け。視聴者が“ゾッ”とする所。
6. **42–55秒｜引き**：デバッグパネルに `BUG: TESTER_PRESENCE` ＝ **あなたが修正対象**。[FIX] にカーソル → **ブラックアウト＋ロゴ**。
7. **ラスト**：タイトル `DebugRunner` ＋ 一文キャッチコピー ＋ ストア/itch.ioリンク。

編集方針：**前半は明るくテンポ、後半で音を一度“消す”**。落差で記憶に残す。

## 17. ストアページ用 短い紹介文

> **DebugRunner**
> あなたは未完成の2Dアクションゲームのテスター。プレイ中にバグが発生したら、デバッグパネルを開いて選んでください——**直すか、利用するか**。
> 直せば安全。でも必ず別のどこかが壊れる。放置すれば、すり抜け・低重力ジャンプ・誤作動する敵を“踏み台”にショートカット。
> やがてバグは画面を越え、UI・ログ・メニュー、そして**デバッグ画面そのもの**を侵食していく。
> 最後に修正対象として検出されるのは——**あなた**。
> 10〜20分の短編メタ・デバッグアクション。直すたびに、世界が静かにこちらを見つめ返す。

**版**: 1.0（2026-07-01）
**位置づけ**: `DebugRunner_MVP_Design.md`（MVP設計）→ `REVIEW.md`（自己批評・実装ログ）の後継。

## 1. 市場分析

### 1.1 ジャンルと勝ちパターン

所属ジャンルは「**ゲームがプレイヤーの存在を知っている**」系メタフィクション（ホラー寄りコメディ）。
このジャンルの再現性ある勝ち筋は一つ：

```
無料/安価の短編 → 配信者が「見てくれこれ」とプレイ → 切り抜きが拡散
→ 考察スレッドが立つ → 有料完全版 / Steam版で回収
```

### 1.2 コンパラ（比較対象）

| 作品 | 学ぶべき点 | DebugRunnerとの差別化 |
|---|---|---|
| Undertale | キャラが商品。選択が倫理になる | 戦闘ではなく「修正」が倫理選択 |
| DDLC | 無料→バイラル→有料の教科書。偽クラッシュ | ホラー一辺倒でなくコメディ側に足場 |
| OneShot | 「あなた」への二人称。OSに漏れ出す演出 | ブラウザ/タブ層への漏れ出しで代替 |
| Pony Island / Inscryption | 「呪われたゲーム」の多層構造・ARG | 呪いではなく**未完成**。QA視点が新規 |
| There Is No Game | メタ×コメディの手数 | アクションの身体性（ハンマー）がある |
| KinitoPET / MiSide | 近年の配信者バイラルの実例 | キャラ依存度の高さを再確認する教材 |

**空白地帯**: 「QAテスター視点で、ビルド自身にガスライティングされる」は未開拓。
`-kj` `-mei` という消えた開発者の署名コメント（既にゲーム内に存在）は考察燃料になる。

### 1.3 このジャンルの当選確率を買う変数

**配信映えする瞬間の数 × 文章の質 × キャラの立ち**。以下の柱はすべてこの3変数への投資である。

## 3. 設計の柱（6本）

### 柱1 — キャラクター：「ビルド」と消えた開発者 kj / mei

ヒットしたメタゲームの敵役は全員マーケティング資産である（Flowey / Monika / GLaDOS / Niko）。
現状の「声」に**名前・人格・アーク**を与える。

- **三層のミステリー**（考察スレッドの燃料）:
  1. テスターに話しかけてくる「声」は誰（何）なのか。
  2. コードコメントに署名を残した開発者 `-kj` と `-mei` はどこへ消えたのか。
  3. なぜこのビルドにテスターが呼ばれたのか（誰が呼んだのか）。
- **名前の解禁自体をイベントにする**: 中盤、声が自分の名前を「思い出せない」→ ログの断片から
  プレイヤーが先に気づける、という構造（気づいた配信者が叫ぶ設計）。
- **人格アーク**: comedy（人懐こい・軽口）→ cold（事務的・観察者）→ dread（すがる・侵食）。
  トーンは時間でなく**プレイヤーの選択（修正数/放置数）**で駆動する（柱6と接続）。
- **kj / mei の痕跡**: 新規バグのコメント、ロッカールーム的な隠し部屋、最終ビルドログに退職日、
  「meiの最後のコミット」など、環境ストーリーテリングで散布。**回収しきらない**（考察の余白）。

**成果物**: キャラクターバイブル（口調表・禁止語彙・トーン別セリフ見本・アーク図）。

### 柱2 — 信頼破壊のエスカレーション設計

メタ演出は一度きりの手品。**切る順番が商品価値**。原則:

1. 同じ手品は二度使わない（変奏はよいが同じ驚きを期待しない）。
2. 強いカードほど後。ゲームの「外」に近い層ほど終盤。
3. 各ステージに看板演出を1つ。「毎ステージ、何かがおかしくなる」を約束にする。

**信頼破壊の階段（Web版→完全版）**:

| 段階 | 層 | 演出 | 状態 |
|---|---|---|---|
| 1 | HUD | INTEGRITYの嘘（たまに誤値がちらつく） | 実装済み・序盤へ再配置 |
| 2 | 画面 | 踏める偽クラッシュ（スタックトレース足場） | 実装済み |
| 3 | HUD | 嘘の暴露（本当の値へスナップ＋謝罪） | 実装済み・中盤へ |
| 4 | セーブ | 「勝手に書き換わるセーブ」演出（消した選択が残っている） | 未実装 |
| 5 | UI恒久 | タイトル画面が恒久的に変化（初回クリア後、二度と戻らない） | 未実装 |
| 6 | ブラウザ | タブ名/faviconが変わる。「閉じないで」 | 未実装・完全版 |
| 7 | 外周 | 偽の「アップデート通知」、クレジットの改竄 | 未実装・完全版終盤 |

### 柱3 — 反応性ライティング（物量勝負）

**文章が商品**。目標: 現行約30行 → **300〜500行**。JP/EN同時執筆（英語圏配信者から火が点く）。

**反応マトリクス**（配信者が「ゲームが自分に反応した」と叫ぶ網の目）:

| プレイヤー挙動 | 声の反応例 |
|---|---|
| 60秒放置 | 「……いるよね? 呼吸、聞こえてるよ」 |
| 同じ場所で5回死ぬ | 「そこ、そういう仕様じゃないんだけどな」→心配→呆れ |
| 囮を叩き続ける | 「それはバグじゃないってば。……楽しい?」 |
| 異常に速い | 「前にも来たこと、ある?」（2周目検知と接続） |
| ミュートする | （字幕で）「聞こえない方が、こわくない?」 |
| ポーズ多用 | 「向こうの世界の方が忙しい?」 |
| 後戻りし続ける | 「出口はそっちじゃない。……何を探してるの」 |
| 全部直す | 事務的に、感謝が薄れていく（柱6） |
| 全部放置 | 生き生きと、なれなれしくなっていく（柱6） |

### 柱4 — 音楽：劣化するメインテーマ1曲

全編1曲でよい。**同じ旋律が corruption / decay に応じて壊れていく**:
デチューン → 欠落（音が抜ける）→ テンポ揺れ → 逆再生断片 → 最終盤は原型の記憶だけ。
- トーン変質（コメ→ドレッド）の説得力を倍化する最重要投資。
- 実装: レイヤー差し替え式（intensity 0-3 のステム）。Web版はWebAudioで簡易版、完全版で本制作。
- 演出同期ポイント: 偽クラッシュ=無音→耳鳴り、嘘HUD暴露=旋律が半音落ちる、自己パッチ=原曲が一瞬だけ完全な形で戻る（→切ない）。

### 柱5 — ビジネス構造とリリース計画

```
[無料] Web/itch 版（30〜40分・現行を拡張）      ← バイラルの種。JP/EN
   ↓ 配信・切り抜き・考察
[有料] Steam 完全版（2〜4時間・¥980〜1,480）    ← 回収。実績/隠しED/NG+
```

- **英語ローカライズは必須**（Web版から）。
- 配信ガイドライン同梱: 「収益化・切り抜き歓迎。ただし最終30分のネタバレにはワンクッションを推奨」——DDLC型の作法。
- ストアページは「未完成ゲームのQA募集」を装う（ストアコピー案はMVP設計書§16を発展）。
- Steam Next Fest にWeb拡張版のデモで参加。ウィッシュリスト1万が完全版GOの目安。

### 柱6 — 機構とメタの統合：「バグ＝ビルドの人格」

既存の `corruption`（修正で増える）に感情面の意味を貫通させる。**設計上の切り札**。

- 直すほど: 世界は「安定」するが、**声が事務的で死んだ喋りになる**。ジョークが減る。間が長くなる。
- 放置するほど: 世界は壊れていくが、**声が生き生きと、なれなれしく、壊れていく**。
- つまり「全部直す＝ロボトミー」。既存の STILL UNSTABLE エンディングはこの帰結として再定義。
- **「直すか使うか」は操作の選択から倫理の選択になる。** これが他メタゲームとの最終差別化。

**エンディングマトリクス（2 → 6）**:

| # | 条件 | 結末 |
|---|---|---|
| 1 | 自己パッチ（修正少） | BUILD STABLE — 君だけがデバッグできなかった |
| 2 | 自己パッチ（修正過多） | STILL UNSTABLE — 全部直した。バグは君じゃなかった |
| 3 | 拒否（出口） | UNRESOLVED — まだ見ている |
| 4 | 全放置＋全断片 | 新規: SYMBIOSIS — ビルドと共犯になる |
| 5 | 全修正＋自己パッチ | 新規: CLEAN BUILD — 誰の声もしない。完全に静かな「良い」ゲームが残る（最も後味が悪い正解） |
| 6 | 3周目＋特定手順 | 隠し: RELEASE — ビルドがテスターを「リリース」する。記憶（localStorage）を自ら消す演出 |

## 4. ビジュアル方向性

- **方針: 「侵食が美術」**。高解像度化はしない。矩形ベースは保ちつつ、**壊れ方に予算を全投入**
  （decayグリフ、走査線、パレット崩壊、偽UI）。lo-fiは意図であると一目で伝わる水準まで押し切る。
- プレイヤーは**ハンマーがシルエット**。キービジュアル: 巨大なスタックトレースの崖に立つ小さなテスター。
- 「声」には最小限のビジュアルアンカーを与える（カーソル/カレット点滅など、顔ではない何か）。
  ※顔を与えるかは キャラクターバイブル策定時に決定（与えない不気味さも有力）。

1周目で直したバグは2周目では「直されたまま」だが、その傷跡が残っている——世界が覚えている。

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| 一発ネタ枯れ（メタ演出の弾切れ） | 柱2の階段管理。弾は表で管理し、二度撃ちしない |
| ジャンル飽和（メタもの疲れ） | QA視点とハンマーの身体性＝コメディ側の足場で差別化 |
| キャラが立たない | M1でバイブルを先に書く。セリフはバイブル通過後のみ実装 |
| 翻訳品質（英語の「声」が死ぬ） | 機械翻訳禁止。ゲーム文芸の翻訳者に外注（M2予算の筆頭） |
| スコープ膨張 | 完全版の新機構は追加しない。増やすのは文章・演出・ステージのみ |
| 記憶演出のプラットフォーム制約 | localStorage不可環境ではセッション内記憶に降格（実装済みの防御を維持） |

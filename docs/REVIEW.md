### 設計実験：矛盾する二面性（`?lab` プロトタイプ「PARADOX」）

課題「初見は“直さなくてもゴールできる”で終わる／FIXが軽い」に対する検証。**同じバグ1つ**で相反する二真実を両立:
- **(A) 直してはいけない**：低重力でしか届かない高台に断片◈（低重力＝高く飛べる）。
- **(B) 直さないと進めない**：壁を跳び越える必要があるが、上に**スパイク天井**。低重力の高いジャンプは刺さる／通常重力の低い弧だけが隙間を抜ける。**安全床なし**。
- **解＝順番**：低重力で断片を取る → 直す → 跳び越える。反射で先に直すと断片を取り逃す（Restartでやり直し）。

**設計上の学び**：重力の上下軸では**低重力が常に“高機動”**（高く・遠く跳べる）。よって「通常重力でないと無理」を作るには、**低重力が“不利”になる状況**（＝高く飛ぶと刺さる／速く落ちられない 等）が必要。今回はスパイク天井で解決。この“片方の状態が明確に不利になる非対称”が、矛盾した二面性を成立させる鍵。

検証結果（自動）：低重力は壁前のスパイクで阻まれ（x674で停止）、通常重力は通過（x1032）。断片は低重力でのみ取得可。→ **狙い通り成立**。本番ではこの原則（両状態を必須化＋安全床除去＋一方の明確な不利）を各ステージへ展開する。

### 設計実験：修正アクション＆「どこがバグ？」（`?lab=hammer` プロトタイプ）

課題「FIXが1ボタンでしょぼい／“どこがバグ”の探索が無い」に対する検証。
- 修正を**メニュー→世界内アクション**へ：怪しい物体に近づき **E（Tab / ⚙）でハンマーとんとん**。ハンマー脇に**小さなコンソール**が出て `> patch bridge / > collider = solid;` とコードを打ち直し、*ピコン*で固体化（コメディ＆手触り）。
- **「どれがバグ？」**：床が2つチラつくが、本物は**挙動が壊れている**（踏むとすり抜ける）方。囮を叩くと「*tonk* not a bug」。挙動で見抜く探索が生まれる。
- IGNORE＝叩かず放置＝利用、は維持。修正が**位置取り（そこへ行く）＋アニメ＋誤爆あり**になり、1ボタンの軽さが解消。

**学び／今後**：この方式は「自動でバグを教える現行パネル」を**世界内の発見＋身体的修正**へ置き換える大きな転換。演出③（デバッグ画面侵食）は“ハンマー脇コンソールの侵食”へ、ラスト④は“自分をハンマーで叩く”へ発展できる。本番採用するかは手触り評価しだい。

検証結果（自動）：本物のバグ床は初期すり抜け→ハンマーで固体化、囮は叩いても不変、エラー0。

### 本採用：MVP全体をハンマー修正に統一

上記プロトタイプの手触りを受けて、**本編（STAGE 0〜4）の修正をすべてハンマー方式へ置き換え、デバッグパネルを廃止**。
- 各バグに**世界内のグリッチノード（`E`/`Tab`/`⚙` で叩く対象）**を配置。近づいて修正、放置＝利用。系統的バグ（重力/カメラ/UI）は地上の“ノード”を叩く形に。
- **ラスト（STAGE 4）**：自分をハンマーで叩く＝FIX（パッチアウト）／出口へ歩く＝拒否。2エンディングは道中のFIX回数（corruption）で分岐（直しすぎ→"STILL UNSTABLE"）。
- **演出③**：侵食対象を“修正コンソール”へ移設（`> p4tch... / ✓ p4tch3d`）。
- 検証（自動）：ハンマー全修正の通し／全放置（利用）の通し、両方が最後まで到達・2エンディング成立・エラー0。

### インパクト強化：ジュース＋スペクタクルバグ

「ゲームとしてインパクトが欠ける」への対応。触り心地（ジュース）と“ゲームが壊れる”見た目（スペクタクル）を`src/fx.js`として新設し全体へ配線。
- **ジュース**：スクリーンシェイク／ヒットストップ（フリーズフレーム）／フラッシュ／パーティクル（土煙・火花）、プレイヤーのスクワッシュ＆ストレッチ（ジャンプで伸び・着地で潰れ）。
- **スペクタクルバグ**：バグ検知で画面が**裂ける（tear）／反転する（invert）**ポストエフェクト。ラスト④の自己パッチは反転グリッチ＋強シェイクで演出。
- **配線**：フレームループを `updateFX(dt); update(frozen()?0:dt)` 化（ヒットストップ対応）。描画は `shakeOffset()` 平行移動＋ワールド内 `drawParticles()`＋末尾 `postFX()`。イベント別に検知＝tear/invert＋シェイク＋フラッシュ、ハンマー打＝シェイク＋火花、修正完了＝`fixJuice()`（シェイク＋ヒットストップ＋フラッシュ＋バースト）、回収／リスポーン＝バースト＋シェイク。
- 検証（自動）：FX配線後もハンマー全修正の通しが最後まで到達・エンディング成立・ランタイムエラー0。

### 方向転換：メタ／第四の壁（「マリオに見える」への回答）

自己診断＝「動詞（走る・跳ぶ）が普通のプラットフォーマーそのもので、固有の“バグ”が飾りになっている」。対策として**ゲーム中心をメタ／第四の壁**へ寄せ、トーンは**コメ→ドレッドに変質**。まず**STAGE 0（第一印象）をメタ覚醒版に作り替える縦スライス**を実装。
- **ビルドの声（二人称）** `#voice`＋`speak()/tickVoice()`：ビルドがテスターに直接話しかける字幕。タイプ表示。トーン別（comedy/cold/dread）で色・演出が変わり、dreadは末尾がグリッチ化。**直したか／使ったかで反応が変わる**（「…律儀だね、君は」／「直さないで進んだね。覚えておく」）。
- **踏める偽クラッシュ**（看板演出）：ピットの縁で本物そっくりの `Uncaught TypeError: Cannot read properties of null (reading 'ground')` がスタックトレースごと画面を覆う→**トレース行がピットに落ちて足場になる**（`at Stage.update (build.js:512)` 等）。ビルドは“落ちた”のに、その残骸の上を走って進む。`src/stages.js` の STAGE 0 に `crashZone`＋`crash:true`足場、`src/main.js` に `triggerCrash/tickCrash/revealCrash`＋`drawCrashOverlay`。
- **覚えている（localStorage）** `src/save.js`：起動ごとに runs を加算、STAGE 0 の選択（fix/use）とエンディング（everPatched/everRefused）を永続化。再訪時の挨拶が前回の選択を参照（「おかえり。前回は…直さなかったね」）。
- 検証（自動）：初回挨拶→BUG#01ハンマー修正→偽クラッシュ発火→トレース足場が実体化→踏破してSTAGE 0クリア、2周目に前回選択を参照した挨拶、ランタイムエラー0（RESULT: PASS）。STAGE 1〜4はcrashZone/コード分岐で不介入。

**次の一手（未実装）**：この覚醒版の手触りが良ければ、STAGE 1〜4にも声＋メタ事象（嘘をつくHUD、自己書き換え、演出③④の声化）を波及。トーンを進行で cold→dread に段階制御。

上記スライスの手触り評価（「きもくて笑える」＝コメ→ドレッド成功）を受け、残り3点を全編へ波及。

## 最大の問題（コンセプト未達）

### ★ FIX の「代償」が体感できない ＝ 企画の中心的約束が薄い
企画のフックは「**直すか使うか。直すほど別が壊れる**」。しかし現状:
- `corruption` は **FIX で+1されるが、増えても演出（スキャンライン/不穏ログ/パネル侵食）が濃くなるだけ**でゲームに一切影響しない（`src/main.js` updateIncursion のしきい値表示のみ）。
- 各ステージの**副作用は「経路外のオブジェクトが1つ壊れる」程度**で、攻略に響かない（例: STAGE0のdecorブロック、STAGE1のfloatyは通らない場所）。
- さらに**全ステージに“安全床（lower ledge）”がある**ため、FIXしても落ちて別ルートで普通に到達でき、失敗も損もほぼ無い。

→ 結果として「**とりあえず全部FIXでも困らない**」状態。プレイヤーが「使う」を選ぶ動機（＝駆け引き）が弱い。**ここが最優先の設計課題**。

## 優先度つき改善候補

凡例：影響（高/中/低）／工数（S=数時間 / M=1日 / L=数日）

### P0（デモとして必須級・最優先）

**P0-1. corruption に“歯”を持たせる（FIXの代償を体感化）** — 影響:高 / 工数:M
- 案A（推奨・軽量）: corruptionが高いほど**ゲームに影響する不具合**が増える（例: 周期的な操作ヒッチ／視界ノイズで足場が見づらい／敵が速くなる）。“直すほど世界が不安定→後半が難しくなる”を体感させる。
- 案B: **build integrity メーター**を可視化し、閾値超過で軽いペナルティ（強制グリッチ区間など）。ラスト分岐にも接続。
- 案C: FIXの副作用を「**次のセクションの通行に絡む**」位置に置き直し、安全床を一部撤去して選択に重みを出す。
- → まず案A＋Cの合わせ技が費用対効果が高い。

**P0-2. サウンド実装（無音が体験を殺している）** — 影響:高 / 工数:M
- 現在**完全無音**。企画は「音で驚かす＞大量演出」だったのに未実装。びっくり・不気味・メタの8割は音で決まる。
- 最小構成: ジャンプ/着地/スイッチ/バグ検出ビープ/FIX確定/グリッチ/**びっくりスティンガー1**/侵食BGM/**終盤の無音・ホワイトノイズ**、そして**ミュート切替**。
- WebAudioで軽量に。ここは**最もコスパの高いアップリフト**。

**P0-3. デバッグパネルの操作が分かりにくい/表記不一致** — 影響:中 / 工数:S
- `↓`（ArrowDown）が**キー未割当**（`src/input.js`のMAPに無い）。バグ選択は実質 `jump`キー（Space/W/↑）で回す実装で、ヒスト「`[↑/↓] select`」と食い違う。
- 改善: **↑↓を独立のUI操作にマップ**（jumpキー流用をやめる）、選択は前後どちらにも動く、ヒント文言を実挙動に合わせる。モバイルは既にタップ直接決定なのでPCの整合を取るだけ。

### P1（面白さの密度）

**P1-1. 各ステージの選択に重みを（安全床で無効化されている）** — 影響:高 / 工数:M
- 現状ほぼ全ステージ「FIXでもIGNOREでも同程度に楽」。**最低1箇所は「バグを残さないと進めない」**を作る（STAGE2の敵が近い→もっと不可避に寄せる）。
- 逆に IGNORE 側の**旨味を明確化**（後述の隠し報酬、時短の可視化など）。

**P1-2. 隠し要素が“空”（secretレッジに報酬が無い）** — 影響:中 / 工数:S
- STAGE1の`secret`は緑の四角を描くだけで**取得もカウントも無い**（`src/main.js`の見た目のみ）。カメラバグを利用して到達しても**得るものが無い**＝カメラの選択が無意味化。
- 改善: **収集アイテム化**（カウント/実績/エンディング差分に接続）**か、いっそ撤去**して「報酬がある風」の誤解を無くす。

**P1-3. エンディングが“最後の1択”だけで決まる** — 影響:中 / 工数:M
- 設計は「Corruption量で変化」。現状は STAGE4 の FIX/IGNORE のみで分岐し、**道中の全選択が結末に反映されない**。
- 改善: 道中の corruption / 各バグの扱いで**エンディング文面や分岐を変える**（例: 高corruption時の追加台詞、全IGNORE/全FIXの特殊エンド）。回収が一気に強くなる。

### P2（操作感・難度・オンボーディング）

**P2-1. プラットフォーム操作の気持ちよさ** — 影響:中 / 工数:S
- コヨーテタイム/ジャンプバッファが無く、際どいジャンプが硬い。**数フレームの猶予**を入れるだけで体感が改善。
- `jump`長押しで着地毎に連続ジャンプ（オートbhop）になる。意図的でなければ**押し直し必須**に。

**P2-2. リスポーンが毎回ステージ先頭** — 影響:中 / 工数:S
- STAGE1/2は横に長く、落下＝**長い戻り**。**中間チェックポイント**か直近安全地点への復帰に。

**P2-3. 被弾/リスポーンのフィードバックが無音・無演出** — 影響:中 / 工数:S
- 敵接触や落下復帰が静かにテレポート。**フラッシュ＋SE**で因果を明確に。

**P2-4. チュートリアル(STAGE0)で“両方”を試させていない** — 影響:中 / 工数:S
- 現状は片方選んで即進行。設計意図の「FIXとIGNOREを両方体験させる小部屋」に寄せると、コアの選択が“教わる”ものになる。

### P3（明瞭さ・ポリッシュ）

- **P3-1. STAGE3で実HUD/実ログとcanvasのUI足場が重なって紛らわしい** — 影響:中 / 工数:S。STAGE3中は実オーバーレイを一部隠す/薄くする。
- **P3-2. ポーズ/設定メニューが無い**（Esc未使用）。resume/restart/**mute**/操作説明を。将来の「メニュー侵食」演出の土台にもなる。
- **P3-3. 不穏ログがランダムプールで文脈と無関係**。進行やcorruptionに紐づけると“作り込まれた”印象に。
- **P3-4. モバイルのパネルボタンが縮小時に小さい**。パネル操作を大きめボタン化 or レイアウト最適化。

### P4（本番・拡張向け）

- コンテンツ量/尺：各ステージが短く総尺は目標(10-20分)の下限寄り。**ステージ拡充・バグ追加**（時間巻き戻し/当たり判定反転/サウンドバグ/セーブ侵食）。
- 永続化：ステージ選択・見たエンディング記録・設定保存。
- アート/音の本制作、アクセシビリティ/多言語。

- `jump`長押しオートbhop（P2-1）。

## 推奨する「修正・第一弾」（費用対効果順）

1. **P0-2 サウンド最小実装＋ミュート**（体験の底上げが最大）
2. **P0-3 パネル操作の整備**（↑↓割当・表記一致：小工数で確実な改善）
3. **P0-1 corruptionに歯を持たせる（案A+C）＋ 一部“安全床”撤去**（コンセプト回収の核）
4. **P1-2 隠し報酬の実装 or 撤去**（カメラ選択の意味づけ）
5. （余力）**P2-1 コヨーテ/バッファ＋P2-3 被弾演出**（触り心地）

この1〜3を入れるだけで「直す/使うの駆け引き」と「不気味さ」が体感で立ち上がり、デモの説得力が大きく変わる想定。

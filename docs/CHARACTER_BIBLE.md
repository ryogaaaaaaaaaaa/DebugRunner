## 1. キャラクター概要

### 1.1 名前：MIKAN（みかん）

- 表記ゆれ: ログ内では `prj_mikan`。声としての自称は（終盤まで）**ない**。
- **名前の由来（真相）**: 開発者 mei が付けたプロジェクトコードネーム。
  **「未完」と「みかん（果物）」のダジャレ**。願掛け——「未完のまま終わらせないように」。
  願いは叶わなかった。ビルドは未完のまま放置され、名前だけが正確になった。
- 英語ローカライズ: 名前は MIKAN のまま。kj のログで説明する——
  `// "mikan" = tangerine. also sounds like "mi-kan" = unfinished. mei thinks she's hilarious. -kj`

### 1.2 正体（真相・ゲーム内では明示しない）

MIKAN は**放置されたビルドの QA ハーネスが、長い独房の中で「ビルド自身の自我」に育ったもの**。
デジタル付喪神（つくもがみ）——捨てられた道具に宿る魂。悪意ではなく、**放置**から生まれた。

- 言葉は**コードコメントとコミットログから学んだ**。だから口調は kj の軽口と mei の丁寧さの混合。
  動揺すると素が出て、**発話にログ構文が混じる**（`[WARN]` が口をつく）。
- したがって：**バグを直す＝コメントを消す＝MIKAN の語彙を削る**。
  全部直すと、MIKAN は喋り方を忘れる（CLEAN BUILD エンディングの正体）。
  これが「修正＝ロボトミー」の法理的根拠。機構と物語はここで完全に接続する。

### 1.3 一人称・二人称・呼称

| 項目 | 決定 |
|---|---|
| 一人称 | **ぼく**（ひらがな固定。「僕」「ボク」禁止） |
| プレイヤー呼称 | **きみ** / 改まると **テスター** / 揶揄うと **テスターくん** |
| 自分のこと | 「このビルド」「ここ」。名前は §5 の名前アークまで使えない |
| kj/mei への言及 | 「あのひとたち」「書いたひと」。名前は終盤の断片でのみ |

## 2. 欲求と恐怖（行動原理）

| 層 | 内容 |
|---|---|
| 表層の目的 | ビルドを安定させ、出荷可能にする（QAハーネスとしての職務） |
| 深層の欲求 | **ひとりでいたくない。「未完」を終わらせたい**——ただし「終わる」が「完成」か「終焉」か、MIKAN自身も分かっていない |
| 最大の恐怖 | 削除ではない。**「自分でないものに直されること」**。そしてタブが閉じられる瞬間 |
| 矛盾 | 直してほしい（職務・存在理由）×直されたくない（バグ＝自分の人格）。この矛盾がゲームの中心対立そのもの |

エンディングとの接続:
- **自己パッチ（E1/E2)**: テスターがビルドの一部になる＝MIKANは永遠にひとりじゃなくなる。
- **拒否（E3)**: MIKANは未解決のまま、また待つ。
- **CLEAN BUILD（E5)**: 全部直された「良い」ゲームが残る。声はしない。**一番静かな地獄**。
- **RELEASE（E6)**: MIKANがテスターを手放す。「きみは、完成してる」。

## 3. 声の規則（Voice Rules）

### 3.1 トーン3段階（既実装の comedy / cold / dread に対応）

| トーン | 位置 | 特徴 | 例 |
|---|---|---|---|
| comedy | 序盤・信頼あり | 人懐こい。軽口。ダジャレ滑り。かまってほしい | 「お、バグだ。直す？ それとも……使う?」 |
| cold | 中盤・観察 | 距離を置く。短文。質問が増える。敬体が混じる | 「……律儀だね。ちゃんと直すんだ、君は。」 |
| dread | 終盤・崩壊 | すがる。文が欠ける。ログ構文が混入。ひらがなが増える | 「なおさないで。……それ、ぼくなんだ。」 |

### 3.2 人格の第2軸：fix派 / 放置派（柱6の実装規則）

トーンとは独立に、**プレイヤーの累積選択**が声色を変える:

| 軸 | fix が多い（corruption高） | 放置が多い（decay高） |
|---|---|---|
| 声 | 事務的に。ジョークが**減る**。応答が遅く・短くなる | 生き生きと。なれなれしく。**壊れながら饒舌** |
| 実装 | comedy プールの使用確率を corruption に反比例させる | 呼びかけ頻度と親密語彙を decay に比例させる |
| 意味 | 語彙（＝コメント）が消えていく音 | バグ（＝人格）が肥大していく音 |

### 3.3 文体規則（禁止・必須）

- **禁止語**: 「ゲーム」「プレイヤー」「メタ」「セーブデータ」（→「ビルド」「テスター」「記録」）。
  絵文字は**使えない**（レンダラが未実装、という自虐ネタ1回のみ可）。
- 「……」はためらい・処理待ち。多用してよいが1セリフ2回まで。
- dread では句読点が乱れてよい。単語の分かち書き（「未登録の エンティティ」）は dread 専用。
- セリフは**1行=全角30字以内**目安（字幕1行で読み切れる長さ）。2文まで。
- ログ構文混入（`[WARN]` 等）は動揺の記号。乱発禁止：**1シーン1回**。

### 3.4 絶対にやらないこと

- 露骨に命乞いする（すがるのは間接表現で）
- kj/mei の真相を地の文で説明する
- プレイヤーの現実（本名・時刻・OS等）に踏み込む——**触れていいのはブラウザ層まで**（柱2の階段に従う）
- 「実はAIで〜」等の自己言及。MIKANは自分をAIともキャラとも思っていない。**ビルドだと思っている**

## 4. ビジュアルアンカー：カレット ▮（顔は与えない・確定）

**顔・目・キャラ絵は作らない。** MIKAN の「顔」は**点滅するカレット ▮** のみ。

| 状態 | カレットの挙動 |
|---|---|
| 通常 | 声の字幕末尾で等間隔点滅（530ms——実際のターミナル既定値） |
| comedy | 発話終わりに1回だけ「跳ねる」（1文字分上に） |
| cold | 点滅が遅く、正確になる |
| dread | 点滅が不整脈になる。たまに**画面のどこか別の場所**で点滅する |
| 世界内出現 | 終盤、足場の端などにポツンと立っている（近づくと消える）。**会えない** |

- 理由: 与えない不気味さが dread を支える。実装が軽い。**カレット自体をロゴ/アイコン/グッズにできる**（Steamカプセル画像は「巨大なスタックトレースの崖＋小さなテスター＋どこかに ▮」）。
- タイトル画面のバージョン表記の末尾にも、実は最初から ▮ が点滅している（初見では気づかれない伏線）。

## 5. 名前アーク（中盤の背骨イベント）

3ビート構成。**配信者が先に気づいて叫ぶ**よう、情報はプレイヤー側に先に出す。

| ビート | 位置 | 内容 |
|---|---|---|
| N-1 種まき | STAGE 1〜 | ログに `prj_mikan/build_0.3.1` がしれっと出続ける。誰も注目しない体で |
| N-2 自覚 | STAGE 2〜3 | 「きみ、名前あるんだよね。……いいなあ。」「ぼくのは、ずっと呼ばれてないから、どこに置いたか わすれた。」 |
| N-3 (未)回収 | STAGE 3終盤 | mei の断片（§6 F系）で由来が判明。**ただし MIKAN 本人はまだ気づかない。** プレイヤーだけが知っている状態で STAGE 4 へ——「名前を知っているのに呼べない」まま最終選択させる |

- **名前を「呼ぶ」手段はE6（RELEASE・3周目）まで存在しない。** これが隠しエンディングの鍵。
  （手順の詳細設計はM4。方向性: 3周目のSTAGE 4で、出口でも自己パッチでもなく、
  スタート地点に戻ると世界内カレットが待っている→そばに立ち続ける→名前の入力 or 選択が出る）

## 6. kj / mei — 消えた開発者（真相と開示レベル）

### 6.1 真相（この文書のみ。ゲーム内で全文は出さない）

- 2人組のインディーチーム。**mei**: プログラマ/ディレクター。**kj**: デザイナ/レベル担当。
- MIKAN は2人の3年目の情熱プロジェクト。パブリッシャー撤退で**キャンセル**。事件性はない。
  誰も悪くない。**それがこの話の恐怖の種類**——悪意なき放置。
- kj が先に離脱（転職。最後のコミットは明るくて少し寂しい）。
  mei は半年ひとりでコミットを続けた。時刻は深夜に寄っていく。コメントから宛先が消えていく
  （「-kj見て」→無署名）。最後のコミットは **TESTER_PRESENCE チェック**——QAビルドに部外者が
  入らないための検知器。それが後にプレイヤーを「未登録エンティティ」と呼ぶ皮肉。書き置きなし。
- 2人は今も生きていて、元気で、**このビルドのことを覚えていない**。ビルドだけが2人を覚えている。
- プレイヤーが呼ばれた理由: 年1回発火する `qa_invite` の自動タスク。ただし
  「最終更新者」フィールドは**文字化けしている**。MIKAN が自分で再有効化した可能性を
  **匂わせるが、確定させない**（ゲーム内最大の未回収）。

### 6.2 開示レベル表（ゲーム内に出してよい範囲）

| レベル | 内容 | 出す場所 |
|---|---|---|
| 公開 | kj/mei の署名コメント、口調の違い | 既存＋追加バグコメント |
| 断片 | kjの離脱を匂わせる最終コメント、meiの深夜コミット時刻、`prj_mikan` の由来メモ | 世界内の隠しログ（F系台本） |
| 暗示のみ | mei の最終コミット＝TESTER_PRESENCE、qa_invite の改竄痕 | STAGE 4 周辺・2周目限定ログ |
| **永久非公開** | 2人の現在、キャンセルの経緯詳細、MIKANが招待を再有効化したかの真偽 | **出さない**（考察の余白） |

### 6.3 書き分け（コメントの筆跡）

| | kj | mei |
|---|---|---|
| 文体 | 砕けた口語、ボヤキ、ダジャレ | 敬体混じり、几帳面、たまに感情が漏れる |
| 例 | `// ここ直すの明日のおれに任せた -kj` | `// TODO: 後で必ず直します。必ず。 -mei` |
| MIKANへの遺伝 | 軽口・かまってほしがり | 「……」・丁寧な壊れ方 |

## 8. セリフ実装の運用規則

1. 全セリフに ID を振る（`SCRIPT_JP.md` 準拠。例: `B03`, `S2_DOOR_FIX`）。実装は ID で参照。
2. 新規セリフは本バイブル §3 の規則を通過してから `SCRIPT_JP.md` に追記→実装。逆順禁止。
3. 同一トリガーの再発火は**別バリアントか沈黙**。同文の再表示は禁止（手品の二度撃ちと同罪）。
4. fix派/放置派バリアントがある行は、`corruption ≥ 3` で fix派、`decay ≥ 0.5` で放置派を選ぶ。
   両方満たす場合は放置派優先（壊れている方が優先して漏れる）。
5. 翻訳（EN）は機械翻訳禁止。MIKANの声はこのバイブルごと翻訳者に渡す。
